## 二、分钟数据架构

### 2.1 数据量估算

```
911只标的 × 240分钟/天 × 250天/年 × 12年（2014-2026）
= 6.5亿条/年 × 12年 = 78亿条
```

**存储估算**：每条约100字节 → ~780GB（压缩后约150GB）

### 2.2 分钟数据表设计

```sql
-- 表命名：ml_cn_{symbol}_history_1m_{year}
CREATE TABLE ml_cn_000001_history_1m_2024 (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    open VARCHAR(50),
    high VARCHAR(50),
    low VARCHAR(50),
    close VARCHAR(50),
    factor DOUBLE DEFAULT 1,
    vol VARCHAR(50),              -- 成交量（股）
    vol_ccy VARCHAR(50),          -- 成交额（元）
    vol_ccy_quote VARCHAR(50),
    confirm TINYINT(1) DEFAULT 1,
    time INT DEFAULT 0,           -- Unix时间戳
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_time (time),
    INDEX idx_time (time)         -- 时间索引很重要
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2.3 分钟数据特殊处理

| 时段 | 说明 | 处理方式 |
|------|------|---------|
| 9:15-9:25 | 集合竞价 | 单独标记或合并到9:30 |
| 9:30-11:30 | 上午连续竞价 | 正常存储 |
| 13:00-14:57 | 下午连续竞价 | 正常存储 |
| 14:57-15:00 | 尾盘集合竞价 | 合并到14:57或15:00 |

**建议增加字段**：
```sql
ALTER TABLE ml_cn_xxx_history_1d_xxx ADD COLUMN (
    is_suspended TINYINT(1) DEFAULT 0,  -- 是否停牌

    limit_down TINYINT(1) DEFAULT 0,    -- 是否跌停
    is_st TINYINT(1) DEFAULT 0          -- 是否ST
);
```

### 3.2 财务数据PIT（Point-in-Time）

**为什么重要**：避免使用未来信息（Look-Ahead Bias）

```
财报期：2024Q1（截止3月31日）
实际发布：2024年4月25日

❌ 错误：在4月1日就使用Q1数据
✅ 正确：只有4月25日之后才能使用
```

**PIT存储方案**：
```sql
CREATE TABLE ml_financial_pit (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    symbol VARCHAR(10) NOT NULL,
    report_period DATE NOT NULL,        -- 报告期：2024-03-31
    announce_date DATE NOT NULL,        -- 公告日：2024-04-25
    indicator VARCHAR(50) NOT NULL,
    value DECIMAL(20,4),
    UNIQUE KEY uk_pit (symbol, report_period, indicator, announce_date),
    INDEX idx_announce (announce_date)  -- 按公告日查询
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 四、数据质量体系

### 4.1 数据校验规则

| 规则 | 条件 | 处理 |
|------|------|------|
| 价格合理性 | close <= 0 | 标记异常 |
| OHLC一致性 | high >= low, high >= open/close | 标记异常 |
| 涨跌幅限制 | 非新股 abs(ret) > 20% | 人工核实 |
| 成交一致性 | 停牌时 vol > 0 | 标记异常 |
| 时间连续性 | 缺失交易日 | 补充或标记 |

### 4.2 多源校验（建议）

```
iFind 数据 ←─────→ 交易所官网/Wind/东财
       ↓
    差异检测
       ↓
   人工确认/修正
```

### 4.3 数据版本管理

财务数据可能被上市公司调整（重述），需保留历史版本：

```sql
CREATE TABLE ml_data_version (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    table_name VARCHAR(100),
    record_key VARCHAR(100),      -- 如：000001_2024Q1_roe
    old_value TEXT,
    new_value TEXT,
    changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    change_reason VARCHAR(100)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 5.1 数据备份策略

```
主库 (RDS) ──同步──▶ 从库 (备份)

```

**RTO/RPO 目标**：
- RTO（恢复时间目标）：< 4小时
- RPO（恢复点目标）：< 1小时
