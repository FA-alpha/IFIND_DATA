# FA Agent 交付契约规范

> 版本: v1.0 | 更新日期: 2026-08-03

---

## 一、设计原则

1. **契约先于实现**：Agent 之间只认契约，不认实现。任一 Agent 可被替换（人工/LLM/纯算法），只要契约不变
2. **三段式交付**：每个交付物 = payload（内容）+ evidence（证据）+ decision（结论与置信度）
3. **全局血缘字段**：每个交付物携带 lineage，可一路回溯到源数据
4. **状态自带**：每个交付物带 gate_status（PASS/REJECT/NEED_HUMAN），编排层据此路由

---

## 二、通用信封（Envelope）

所有 Agent 交付物的外层统一格式：

```yaml
Envelope:
  artifact_id:      # 全局唯一, 如 FAC-20260803-0031
  artifact_type:    # factor | model | allocation | strategy | backtest | execution | review | risk_assessment
  producer_agent:   # 生产者Agent名称
  version:          # 版本号
  created_at:       # 创建时间
  
  lineage:          # 血缘追溯 —— 亏损可追溯的关键
    parents: [...]  # 上游artifact_id列表
    source_data:    # 数据快照ID和时间窗
      - snapshot_id: "SNAP-20260803-001"
        time_window: "2025-08-03 ~ 2026-08-03"
  
  gate_status:      # PASS | REJECT | NEED_HUMAN
  confidence:       # [0,1] 生产者对本产出的置信度
  reason:           # 结论理由(供人工审核 & 下游Agent参考)
  
  payload: {...}    # 见下方各Agent专属定义
  evidence: {...}   # 见下方各Agent专属定义
```

## 三、各 Agent 交付契约

### ① 因子挖掘 Agent → 因子交付物

```yaml
payload:
  expression:        # DSL表达式, 如 cs_rank(ts_zscore(volume,20)*ts_mean(ret,5))
  factor_class:      # 量价 | 财务 | 估值 | 曲面 | 相关性
  target_universe:   # A股 | 美股 | 印度期权 | ...
  horizon:           # 5min | 1d | ...
  economic_logic:    # 经济学含义(必填, 拒绝无逻辑的纯挖掘因子)

evidence:
  ic_mean:           # 样本内IC均值
  ic_ir:             # IC信息比率
  ic_decay_curve:    # 衰减曲线[lag1..lagN] —— 判断因子寿命
  turnover:          # 因子换手
  corr_to_existing:  # 与现有因子池最大相关系数(去冗余)
  coverage:          # 标的覆盖率

# 准入红线(不满足→gate_status=REJECT):
#   - ic_ir >= 0.3
#   - corr_to_existing < 0.7      # 防止重复因子
#   - economic_logic != null      # 强制经济学解释
```

### ② 模型 Auto-Research Agent → 模型交付物

```yaml
payload:
  model_family:      # LightGBM | Transformer | ... 
  input_factors:     # 引用的factor artifact_id列表(血缘)
  target_definition: # 预测目标 —— 必须是组合目标, 非纯MSE
  hyperparams:       # 最终超参
  model_uri:         # 模型文件存储位置

evidence:
  is_metrics:        # 样本内: IC/Sharpe
  oos_metrics:       # 样本外(必须!): IC/Sharpe/最大回撤
  pbo:               # 过拟合概率(Probability of Backtest Overfitting)
  feature_importance: # 特征重要性
  regime_stability:  # 不同市场状态下的表现一致性

# 准入红线:
#   - oos_sharpe >= 阈值 AND oos_sharpe/is_sharpe >= 0.6   # 样本外不能垮
#   - pbo < 0.5                                            # 过拟合概率红线
#   - 目标函数对齐组合目标(非纯预测精度) —— 人工/规则校验
```

### ③ 优化器 Agent → 配置交付物

```yaml
payload:
  target_weights:    # {symbol: weight}
  target_exposure:   # 净敞口
  leverage:          # 杠杆率
  objective_used:    # 用了什么目标函数(含置信度加权)

evidence:
  expected_return:   # 预期收益
  expected_risk:     # 预期风险
  turnover_from_prev: # 相对上期换手率
  constraint_report: # 每条约束是否binding(行业/杠杆/单标的)

# 准入红线:
#   - 所有 risk_limits 约束满足 (硬校验, 违反即REJECT)
#   - 换手 <= 上限
```

### ④ 策略编写 Agent → 策略包

```yaml
payload:
  strategy_id:       # 策略唯一ID
  engine_type:       # A_dl_stock | B_global_ls | C_airbag | D_vol_surface
  config:            # 完整可部署配置(参数/标的/频率/执行算法)
  model_refs:        # 引用的model artifact_id
  code_or_template:  # 策略代码或模板引用

evidence:
  logic_check:       # 逻辑一致性校验(配置与模型是否匹配)
  dry_run_result:    # 空跑一遍无报错

# 准入红线:
#   - dry_run 通过
#   - config 通过 schema 校验
#   - 引用的 model/allocation 均为 PASS 状态
```

### ⑤ 策略回测 Agent → 回测报告

```yaml
payload:
  strategy_id:       # 策略ID
  test_period:       # 分训练/验证/样本外三段
  markets:           # 多市场

evidence:
  returns:           # 净值曲线
  sharpe:            # 夏普比率
  calmar:            # 卡尔玛比率
  max_dd:            # 最大回撤
  stress_tests:      # 极端情景: 2015股灾/2024熔断/黑天鹅
    - scenario: "2015股灾"
      loss: -12%
    - scenario: "2024熔断"
      loss: -6%
  regime_breakdown:  # 牛/熊/震荡分段表现
  capacity:          # 容量估计
  slippage_model:    # 含交易成本/撤单限制的真实模拟
  multiple_testing_adj: # 多重检验校正后的显著性

# gate_status决策规则:
#   - 全部通过 → PASS → 进入人工审批闸门L1
#   - 样本外/压力测试不达标 → REJECT → 回灌因子挖掘
#   - 边际情况 → NEED_HUMAN
```

### ⑥ 实盘交易 Agent → 执行状态流

```yaml
payload:  # 实时流
  strategy_id:       # 策略ID
  orders:            # 订单执行明细
  positions:         # 实时持仓
  execution_algo:    # TWAP/VWAP/被动挂单

evidence:
  fill_rate:         # 成交率
  slippage_actual:   # 实际滑点 vs 预期
  cancel_count:      # 撤单计数(对撤单限制)
  live_vs_backtest:  # 实盘与回测偏离度 —— 关键监控

# 触发规则:
#   - live_vs_backtest 偏离超阈值 → NEED_HUMAN(L2)
#   - 撤单接近限额 → 自动转被动挂单
#   - 回撤触及红线 → kill_switch(L3)
```

### ⑦ 复盘 Agent → 复盘/回灌包

```yaml
payload:
  target_strategy:   # 目标策略
  attribution:       # 归因: 收益/亏损来自哪个因子/哪个市场/哪段时间
    - factor_id: "FAC-031"
      contribution: -2.5%
    - source: "行业集中度"
      contribution: -1.2%
  decay_detected:    # 哪些因子衰减
    - factor_id: "FAC-031"
      ic_before: 0.05
      ic_after: -0.01
  regime_shift:      # 检测到的市场结构变化
    detected: true
    from: "震荡"
    to: "趋势下跌"
  feedback_actions:  # 结构化回灌建议 → 可执行指令
    - target: "因子挖掘Agent"
      action: "FAC-031标记衰减，暂停使用"
    - target: "优化器Agent"
      action: "收紧行业约束至12%"
```

### ⑧ 风控 Agent → 风控评估/告警/处置

#### 8.1 风险评估报告（事前）

```yaml
payload:
  target_type:       # strategy | allocation | model
  target_id:         # 评估对象的artifact_id
  risk_assessment:
    overall_score:   # 0-100 风险评分
    risk_level:      # LOW | MEDIUM | HIGH | CRITICAL
    exposures:       # 风险暴露明细
      - type: industry
        detail: {银行: 0.25, 科技: 0.18}
        breach: false
      - type: factor
        detail: {size: 0.3, value: -0.2, momentum: 0.5}
        breach: false
      - type: concentration
        detail: {top5_weight: 0.35}
        breach: false
    stress_test:     # 压力测试结果
      - scenario: "2015股灾"
        expected_loss: -15%
      - scenario: "2024熔断"
        expected_loss: -8%
    capacity:        # 容量评估
      estimated_aum: 5亿
      slippage_at_1x: 0.1%

evidence:
  calculation_method: # 使用的风险模型
  data_snapshot:      # 数据快照ID
  assumptions:        # 假设条件

gate_status:          # PASS | NEED_REVIEW | REJECT
recommendation:       # 通过/建议调整/否决的理由
```

#### 8.2 实时告警（事中）

```yaml
payload:
  alert_type:        # DRAWDOWN | EXECUTION_DRIFT | MARKET_ANOMALY | CANCEL_LIMIT
  severity:          # INFO | WARNING | CRITICAL | EMERGENCY
  strategy_id:       
  current_state:
    nav: 0.92
    drawdown: 0.08
    water_level: "L2"
  trigger_condition: # 触发条件
  suggested_action:  # REDUCE_LEVERAGE | PAUSE | HALT | MANUAL_REVIEW

evidence:
  timeline:          # 触发时间线
  related_positions: # 相关持仓
  market_context:    # 市场背景
```

#### 8.3 风控复盘（事后）

```yaml
payload:
  period:            # 复盘周期
  strategies:        # 涉及的策略
  risk_attribution:  # 风险归因
    - source: "因子FAC-031衰减"
      contribution: -2.5%
    - source: "行业集中度过高"

      suggested: 0.12

feedback_actions:    # 回灌指令
  - target: "优化器Agent"
    action: "收紧行业约束至12%"
  - target: "因子挖掘Agent"
    action: "FAC-031标记衰减，暂停使用"
```

## 四、契约治理总表

| Agent | 输入 | 输出类型 | 最硬的准入红线 |
|-------|------|---------|---------------|
| 因子挖掘 | 数据+回灌 | factor | IC_IR≥0.3 & 有经济逻辑 & 去冗余 |
| 模型研究 | factor | model | 样本外不垮 & PBO<0.5 |
| 优化器 | model | allocation | 全部风控约束满足 |
| 策略编写 | model+alloc | strategy | dry_run通过 & 引用全PASS |
| 回测 | strategy | backtest | 样本外+压力测试达标 |
| 交易支持 | strategy(实盘) | execution | 实盘偏离/回撤监控 |
| 复盘 | execution | review→回灌 | 产出可执行回灌指令 |
| 风控 | 全程 | risk_* | 风险评分+处置建议 |

## 五、血缘追溯示例

回答"这笔亏损来自哪"：

```
执行亏损 EXE-...-088
  └─ strategy STR-...-012
       └─ model MDL-...-045
            └─ factor FAC-...-031 (震荡市IC转负)
                 └─ source_data: 中证1000 tick, 2026-06窗口

→ 复盘Agent自动定位到 FAC-031, 生成下线指令回灌因子挖掘
```
