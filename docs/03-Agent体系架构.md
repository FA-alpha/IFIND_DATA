# FA Agent 自动化策略开发体系 - Agent 架构设计

> 版本: v1.0 | 更新日期: 2026-08-03

---

## 一、体系目标与闭环定义

核心是把研究到交易的完整链路交给 Agent 协作完成，形成一个能自我迭代的闭环。

```
        ┌──────────────────── 反馈回路 ─────────────────────┐
        │                                                    │
   因子挖掘 → 模型研究 → 优化配置 → 策略编写 → 回测 → 交易 → 复盘
        ↑                                                    │
        └──────────── 复盘产出的问题回灌到因子/模型 ───────────┘
                              │
                       [人工干预入口]  ← 关键决策点必须可人工卡位
```

**闭环关键**：复盘 Agent 的产出必须能结构化回灌到因子挖掘和模型研究，否则就只是自动化流水线，不是自进化体系。

---

## 二、八个 Agent 职责边界

| # | Agent | 输入 | 核心职责 | 产出物 |
|---|-------|------|---------|-------|
| 1 | **因子挖掘 Agent** | 原始数据、复盘反馈 | DSL生成/搜索因子，IC/衰减初筛 | 候选因子池 |
| 2 | **模型 Auto-Research Agent** | 候选因子 | 选模型/调参/训练，评估预测→组合目标对齐 | 训练好的模型+评估卡 |
| 3 | **优化器 Agent** | 模型信号+置信度 | 目标感知组合优化，守约束边界 | 目标权重/敞口方案 |
| 4 | **策略编写 Agent** | 模型+权重方案 | 把研究成果翻译成可执行策略配置/代码 | 可部署策略包 |
| 5 | **策略回测 Agent** | 策略包 | 多周期/多市场回测、压力测试、过拟合检测 | 回测报告+通过/否决 |
| 6 | **实盘交易 Agent** | 通过的策略 | 执行监控、撤单管理、异常告警、拆单 | 交易执行+实时状态 |
| 7 | **复盘 Agent** | 实盘结果 | 归因分析、衰减检测、结构变化识别 | 复盘报告→回灌 |
| 8 | **风控 Agent** | 全程监控 | 事前评估+事中监控+事后复盘 | 风险评估/告警/处置建议 |

## 三、风控 Agent 详细设计

### 3.1 与 Guardrail 护栏的区别

| 对比项 | Guardrail 护栏 | 风控 Agent |
|-------|---------------|-----------|
| **性质** | 被动规则引擎 | 主动智能体 |
| **触发** | 每个产出物过审 | 实时监控 + 主动扫描 |
| **能力** | 硬规则校验 | 动态判断 + 预警 + 建议 |
| **决策** | PASS/REJECT 二元 | 风险评分 + 处置建议 |
| **覆盖** | 事前拦截 | 事前+事中+事后全覆盖 |

### 3.2 风控 Agent 职责

```
┌─────────────────────────────────────────────────────────────────┐
│                       风控 Agent (Risk Agent)                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1️⃣ 事前风控 (Pre-Trade)                                        │
│     - 策略上线前的风险评估                                        │
│     - 组合风险暴露分析 (行业/风格/因子)                           │
│     - 极端情景压力测试                                           │
│     - 流动性/容量评估                                            │
│                                                                 │
│  2️⃣ 事中风控 (Real-Time)                                        │
│     - 实时仓位监控                                               │
│     - 回撤预警 (触发水位线)                                       │
│     - 市场异常检测 (熔断/极端波动)                                │
│     - 执行偏离监控 (实盘 vs 回测)                                 │
│     - 撤单频次监控                                               │
│                                                                 │
│  3️⃣ 事后风控 (Post-Trade)                                       │
│     - 风险归因 (亏损来自哪)                                       │
│     - 因子衰减检测                                               │
│     - 市场结构变化识别                                           │
│     - 风控规则迭代建议                                           │
│                                                                 │
│  4️⃣ 动态决策                                                    │
│     - 市场状态识别 → 动态调整风控参数                             │
│     - 边界情况判断 (规则无法覆盖的灰色地带)                        │
│     - 紧急处置建议 (降杠杆/平仓/暂停)                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.3 风控 Agent 工具集

| 工具 | 功能 |
|------|------|
| `risk_calculator` | 计算 VaR/CVaR/波动率/最大回撤 |
| `exposure_analyzer` | 分析行业/风格/因子暴露 |
| `stress_tester` | 历史情景压力测试 |
| `regime_detector` | 市场状态识别 (牛/熊/震荡) |
| `anomaly_detector` | 市场异常检测 |
| `liquidity_estimator` | 流动性/容量评估 |
| `alert_dispatcher` | 告警分发 (Lark/邮件) |

### 3.4 风控 Agent 在流程中的位置

```
                                    风控Agent(全程监控)
                                          │
        ┌─────────────────────────────────┼─────────────────────────────────┐
        │                                 │                                 │
        ▼                                 ▼                                 ▼
   [事前评估]                        [事中监控]                        [事后复盘]
        │                                 │                                 │
因子→模型→优化→策略──▶[风险评估]──▶回测──▶[L1]──▶实盘──▶[实时告警]──▶复盘──▶[风控复盘]
                           │                          │                    │
                      PASS/调整/否决            触发水位线→降杠杆        回灌建议
                                              触发红线→HALT
```

## 四、总体技术架构

```
┌────────────────────────────────────────────────────────────────┐
│  L5  人机协同层  (Human-in-the-Loop)                            │
│  审批工作台 · 干预入口(L0-L3) · 决策看板 · 一键接管               │
├────────────────────────────────────────────────────────────────┤
│  L4  编排调度层  (Orchestrator)                                 │
│  工作流引擎(DAG) · Agent间消息路由 · 状态机 · 审批闸门 · 血缘追踪  │
│         ↑ 复盘反馈回灌到因子挖掘/模型研究                         │
├────────────────────────────────────────────────────────────────┤
│  L3  Agent 智能体层                                             │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐       │
│  │因子挖掘│→│模型研究│→│优化器  │→│策略编写│→│回测    │       │
│  └────────┘ └────────┘ └────────┘ └────────┘ └────────┘       │
│       │          │          │          │          │            │
│       │     ┌────────┐ ┌────────┐ ┌────────┐      │            │
│       └────→│风控    │←│实盘交易│←│复盘    │←─────┘            │
│             └────────┘ └────────┘ └────────┘                   │
│  每个Agent = LLM推理核 + 专用工具集 + 记忆(向量库) + 约束护栏     │
├────────────────────────────────────────────────────────────────┤
│  L2  工具与执行层  (Tools / MCP Servers)                        │
│  因子DSL引擎 · 训练框架 · cvxpy优化器 · 回测引擎 · 交易网关       │
│  (Agent通过标准化工具接口调用,不直接写底层代码)                   │
├────────────────────────────────────────────────────────────────┤
│  L1  数据与风控底座  (所有层共享)                                │
│  统一数据湖 · 特征/模型/策略注册表 · 全局风控红线 · 实验追踪(血缘) │
└────────────────────────────────────────────────────────────────┘
```

## 五、单个 Agent 内部结构（统一范式）

```
┌─────────────── Agent 内部 ───────────────┐
│  1. 感知(Input)   ← 从消息总线接任务       │
│  2. 记忆(Memory)  ← 向量库:历史经验/失败案例│
│  3. 推理(LLM核)   ← 规划下一步动作          │
│  4. 工具调用(Tools)← 通过MCP调专用工具      │
│  5. 护栏(Guard)   ← 风控/约束校验,越界即拒  │
│  6. 产出(Output)  → 结构化交付物+置信度+理由│
└──────────────────────────────────────────┘
```

**关键点：**
- LLM 负责规划和决策（"下一步该搜哪类因子/该否决这个策略吗"）
- 计算不靠 LLM，靠调用确定性工具（IC 计算、回测、优化都是工具，结果可复现）
- 每个产出都带置信度+理由，供上游 Agent 和人工判断

## 六、各 Agent 工具集配置

| Agent | 挂载的工具(MCP Server) | LLM主要干什么 |
|-------|----------------------|--------------|
| 因子挖掘 | 因子DSL引擎、IC计算器、数据查询 | 规划搜索方向、组合算子、判断因子经济学含义 |
| 模型研究 | AutoML、超参搜索、训练框架 | 选模型族、设计验证方案、判断是否过拟合 |
| 优化器 | cvxpy求解器、协方差估计 | 设定目标函数权重、解读优化结果合理性 |
| 策略编写 | 代码模板库、配置生成器 | 把方案翻译成策略配置、校验逻辑一致性 |
| 回测 | 回测引擎、压力测试、多重检验 | 设计测试场景、解读结果、给通过/否决建议 |
| 交易支持 | 交易网关、撤单计数器、告警 | 监控执行质量、判断异常、决定拆单/降级 |
| 复盘 | 归因引擎、衰减检测 | 归因亏损来源、识别市场结构变化、生成回灌建议 |
| 风控 | 风险计算器、暴露分析、压力测试 | 评估风险等级、识别异常、给处置建议 |

## 七、编排层设计

### 7.1 技术选型建议

| 组件 | 推荐选型 | 备选 |
|------|---------|------|
| 工作流编排 | LangGraph | Temporal |

### 7.2 工作流状态机

```
[因子候选] --初筛通过--> [模型训练] --评估通过--> [组合优化]
    │否决                    │否决                  │
    ↓                        ↓                      ↓
 [归档/回灌]            [归档/回灌]          [策略编写]
                                                  │
                                            [回测] --通过?--> [人工审批闸门L1]
                                                  │否决              │批准
                                                  ↓                  ↓
                                             [回灌]           [实盘小仓]
                                                                    │
                                                              [监控/复盘]
                                                                    │
                                                    ┌───────────────┤
                                              [衰减/异常]      [表现良好]
                                                    ↓               ↓
                                              [回灌+人工L2]    [扩仓/保留]
```

## 八、人工闸门分级

| 级别 | 场景 | 处置 | 是否阻断 |
|------|------|------|---------|
| L0 全自动 | 因子初筛、常规回测 | 仅留痕 | 否 |
| L1 单人审批 | 策略 回测→实盘 | 审批工作台点批准 | 是（等待批准）|
| L2 双人复核 | 加杠杆/新市场/大额调仓/改红线 | 两人独立批准 | 是 |
| L3 紧急接管 | 回撤触线/市场异常/Agent行为异常 | kill_switch→转全人工 | 是（立即冻结）|

## 九、非功能性需求

| 类别 | 需求 |
|------|------|
| 人工干预 | 每个Agent之间有"审批闸门"；关键节点必须人工确认或可一键接管 |
| 可追溯 | 每个因子/模型/策略/交易有唯一ID和完整血缘，能回答"这笔亏损来自哪个因子" |
| 风控前置 | 风控红线是所有Agent都必须遵守的全局约束，硬编码不可覆盖 |
| 防过拟合 | 回测Agent必须内置样本外验证、多重检验校正 |
| 可解释 | Agent的决策要能给出理由，供人工审核 |
| 降级机制 | Agent失效时能降级到人工/半自动，而非停摆 |

## 十、分阶段落地建议

| 阶段 | 自动化程度 | 目标 |
|------|-----------|------|
| P1 单Agent工具化 | 各Agent独立运行，人工串联 | 先把每个Agent的工具做扎实、产出标准化 |
| P2 半自动流水线 | Agent自动流转，每个闸门人工审批 | 打通编排层，验证交付契约 |
| P3 闭环自迭代 | 复盘自动回灌，仅关键节点人工 | 形成自进化，L1/L2闸门保留 |
| P4 规模化 | 多策略并行，人工只管异常 | 只在L2/L3介入 |
